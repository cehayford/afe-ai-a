2Development level: the free setup (recommended now)

While we build, Afe runs on free services, not on AWS. It is one server running the same Docker images that will run on AWS, plus free services around it for files, email, domain, monitoring and tests. Cost: $0 a month. The only spend is a domain name, about $10–15 a year.

Nothing here is tied to one vendor. The app reads everything from settings, so at beta the same images move to AWS and only the settings change (see "Moving to AWS at beta" below).

Setup guide

Allow about half a day. Commands run on the server unless it says otherwise.

1. Accounts - Oracle Cloud: - Sign up at cloud.oracle.com. A card is needed to check who you are, and Always Free resources are never charged. - Choose the home region carefully, because it can't be changed. South Africa (Johannesburg) is closest to Accra. If it has no ARM capacity, UK South (London) or Germany Central (Frankfurt) are good second choices. - Once the server runs, upgrade the account to Pay As You Go. It stays free within the Always Free limits, and Oracle doesn't reclaim idle servers on paid accounts. Set a budget alert of $1 in Oracle so nothing chargeable goes unnoticed. - Cloudflare: add the domain (buy one at cost through Cloudflare Registrar, or move an existing one). Enabling R2 asks for a card; the free allowance isn't charged. - Resend (or Brevo), and UptimeRobot.

2. Create the server (Oracle Cloud console) - Compute > Instances > Create: - image Ubuntu 24.04 (aarch64); - shape VM.Standard.A1.Flex with 4 OCPUs and 24 GB; - boot volume 100 GB; - your SSH public key. - If you'll use Caddy with open ports: in the instance's subnet security list, allow TCP 80 and 443 from anywhere, and TCP 22 only from your own IP address. Oracle's Ubuntu images also block these ports in the server's own firewall, so open them there too:

bash sudo iptables -I INPUT 6 -p tcp -m state --state NEW -m multiport --dports 80,443 -j ACCEPT sudo netfilter-persistent save

  • If you'll use Cloudflare Tunnel: open nothing except SSH from your IP.

3. Install Docker and Git

bash curl -fsSL https://get.docker.com | sudo sh sudo usermod -aG docker ubuntu && newgrp docker sudo apt-get install -y git

4. Cloudflare R2 - Create three buckets: afe-dev-media-public, afe-dev-private and afe-dev-backups. - On afe-dev-media-public only, turn on public access: its r2.dev address, or better a custom domain such as media.dev.afe.example. That address is AFE_MEDIA_URL. - Create an API token: R2 > Manage API tokens > Object Read & Write, limited to the three buckets. Note the access key, the secret, and the endpoint https://<account-id>.r2.cloudflarestorage.com.

5. Email - In Resend, add the domain (e.g. dev.afe.example) and add the DNS records it shows (SPF and DKIM) in Cloudflare. - Create an API key. - Until the domain is verified, Resend only delivers to your own address.

6. Address: choose one Two addresses: the website (dev.afe.example) and the API for the mobile app (api.dev.afe.example). - Caddy (simplest): - In Cloudflare DNS, add A records dev and api.dev pointing at the server's public IP, set to DNS only (grey cloud). - Set SITE_ADDRESS=dev.afe.example and API_ADDRESS=api.dev.afe.example in .env. Caddy gets both certificates on first start. - Afterwards you can turn on the orange cloud with SSL mode Full (strict). - Cloudflare Tunnel (no open ports): - In Zero Trust > Networks > Tunnels, create a tunnel and copy its token. - Add two public hostnames, dev.afe.example and api.dev.afe.example, both sending traffic to http://caddy:80. - In .env, set SITE_ADDRESS=http://dev.afe.example, API_ADDRESS=http://api.dev.afe.example and TUNNEL_TOKEN=.... - Start with --profile tunnel. - Either way, Caddy passes each visitor's real address to the app, so rate limits work per person.

7. Get the code and fill in the settings

bash git clone https://github.com/<you>/afe-ai.git && cd afe-ai/deploy/free-server cp .env.example .env openssl rand -hex 32 # run 3 times: AFE_SECRET_KEY, AFE_PII_HASH_KEY, POSTGRES_PASSWORD nano .env # the address, R2, email and backup settings

For a private repository, use gh auth login or a read-only deploy key.

8. Start Afe

```bash docker compose up -d --build # the first build on ARM takes 5–10 minutes

or, with Cloudflare Tunnel: docker compose --profile tunnel up -d --build

docker compose ps # every service "running"; "migrate" exited 0 docker compose logs -f api worker ```

9. Demo data and a first sign-in

```bash docker compose run --rm api python -m app.cli seed-demo --force

Staff sign in with the demo password, then an authenticator code:

docker compose run --rm -e AFE_DEBUG=1 api python -m app.cli totp reviewer

Your own admin account:

docker compose run --rm api python -m app.cli create-user --role admin --name "" --phone 024XXXXXXX ```

10. Backups: check them now, not when they're needed

bash docker compose run --rm backup now # one backup straight away docker compose run --rm backup list # it should be in R2

Backups then run every night at BACKUP_HOUR (01:00 UTC by default) and are kept 30 days.

Restore drill: do it once now, and again before beta.

bash docker compose stop api worker docker compose run --rm backup restore afe-20261001-0100.dump docker compose start api worker

11. Monitoring - In UptimeRobot, add an HTTPS monitor for https://dev.afe.example/, alerting your email. - On the server, docker compose logs api | grep unhandled_error finds an error by the reference the user was shown. - Failed jobs log worker_job_failed.

12. The mobile app on this server - Build it with --dart-define=AFE_API_URL=https://api.dev.afe.example --dart-define=AFE_WEB_URL=https://dev.afe.example (see mobile/README.md). - Testers can install the debug APK that GitHub Actions builds, or a build from flutter build apk.

13. Updating

bash cd ~/afe-ai && git pull && cd deploy/free-server && docker compose up -d --build

Migrations run by themselves before the API starts. GitHub Actions has already tested the push.

Optional: - Real test accounts: Paystack test keys and the WhatsApp test number, set as in .env.example. - The ClamAV virus scanner: docker compose --profile scan up -d, and set AFE_MALWARE_SCANNER=app.modules.media.scan.ClamAvScanner. The server has the memory for it.

Moving to AWS at beta

  1. Images: push the same afe-api and afe-web images to ECR. The CI workflow already builds them.
  2. Infrastructure: apply infra/terraform/staging and fill in its secrets.
  3. Database: take a backup (docker compose run --rm backup now) and restore it into RDS with pg_restore --no-owner. Or start beta clean with only real data.
  4. Files: copy R2 to S3 with rclone sync r2:afe-dev-media-public s3:<staging-public-bucket> (and the same for the private bucket).
  5. Settings: - Email: ResendEmail to SesEmail. - Storage: remove AFE_S3_ENDPOINT_URL and the R2 keys (AWS uses the task's IAM role). - Turn off AFE_ALLOW_FAKE_PROVIDERS once the real providers are in.
  6. Scheduled jobs: the worker runs without --with-daily, because EventBridge runs the daily jobs on AWS.
  7. Keep the free server as the demo and training site, or switch it off.

Fallback: development on AWS

If Oracle's free server isn't available, the same setup runs on one small AWS server, paid from the Free Tier credits. The next two sections cover the AWS Free Tier and that option.

3The AWS Free Tier today

AWS changed its Free Tier on 15 July 2025, and what you get depends on when the account was opened:

  • New accounts (opened after 15 July 2025) start on a Free plan:
  • $100 of credits on sign-up, and up to $100 more for completing the "Explore AWS" activities: up to $200 in total.
  • The Free plan lasts 6 months or until the credits run out, whichever comes first. You are never charged on it; to keep going, upgrade to the Paid plan before it ends. Unused credits carry over and expire 12 months after the account was opened.
  • Some services are not available on the Free plan. Cape Town is an opt-in region that must be enabled first, so build the development environment in Ireland.
  • Older accounts keep the old 12-month offer: 750 hours a month of a t2/t3.micro server and of a db.t3/t4g.micro database, 20 GB of database storage and 5 GB of S3.
  • Always free, on any plan:
  • CloudFront: 1 TB and 10 million requests a month.
  • Data out to the internet: 100 GB a month.
  • CloudWatch: 10 metrics, 10 alarms and 5 GB of logs.
  • SNS: 1 million publishes.
  • Lambda: 1 million requests.
  • Systems Manager Parameter Store: standard parameters.
  • AWS Budgets alerts.
  • Never free, and the usual surprise bills: NAT gateways, load balancers, Multi-AZ databases, public IPv4 addresses (about $3.65 a month each) and anything left running after testing.

How the development server is set up

  • Server: t4g.small, an ARM (Graviton) server with 2 GB of memory, running Ubuntu 24.04 with Docker. A t4g.micro (1 GB) is too small for the API, website and PostgreSQL together.
  • Afe's images build for ARM as they are: the Python and Node base images, and psycopg, all come in ARM versions.
  • Settings:
  • AFE_DEBUG=0 with AFE_ALLOW_FAKE_PROVIDERS=1 (already in backend/app/config.py), so the app runs as it will in production but with the test ID-check, SMS and payment providers.
  • AFE_STORAGE_BACKEND=s3, pointing at real S3 buckets.
  • AFE_MALWARE_SCANNER stays on the fake scanner. ClamAV needs about 1.5 GB of memory of its own.
  • Scheduled jobs:
  • One python -m app.cli worker container runs the every-minute and 5-minute jobs.
  • Cron on the server runs the 5 daily jobs.
  • Security:
  • The firewall (security group) opens only ports 80 and 443 to everyone, and 22 only to your own IP address. Better still, use Session Manager and open no SSH port at all.
  • Turn on MFA for the root user, and do day-to-day work as a separate IAM user or with IAM Identity Center.
  • The server gets an IAM role for S3 and SES, so there are no access keys on disk.
  • Guard rails:
  • AWS Budgets alerts at $1, $10 and $25.
  • Free Tier usage alerts.
  • A Cost Anomaly Detection monitor.
  • Never create a NAT gateway or load balancer in the development account.
  • Outside AWS, also free:
  • GitHub Actions for CI, 2,000 minutes a month for private repositories. Run the backend tests on PostgreSQL there, since they pass on PostgreSQL 17.
  • Sentry's free Developer plan for error tracking.

5Beta (staging): what the Terraform costs

infra/terraform/staging builds the production shape at small scale: - ECS Fargate for the API (with the ClamAV virus scanner beside it), the website and the worker; - RDS PostgreSQL; - an Application Load Balancer and one NAT gateway; - four S3 buckets and CloudFront; - SES, alarms, and daily backups copied to a second region.

Two cost fixes are now in the Terraform: 1. A free S3 gateway endpoint. Container images come from S3 and no longer pass through the NAT gateway. Without it, image downloads could have cost $500–1,400 a month. 2. One always-on worker task for the frequent jobs, instead of about 120,000 separate task starts a month.

6Production cost sheet

Production is the staging Terraform with more capacity: - API and website tasks in two availability zones; - a Multi-AZ database one size up; - one NAT gateway per zone; - AWS WAF in front of the load balancer; - logs kept 90 days, and backups kept a year in a second region.

Region (decision B11): - Cape Town is closest to Accra, with lower delay for users and for mobile money callbacks, and keeps data in Africa. It costs about 20–25% more. - Ireland is cheaper and has every AWS service.

7Ways to spend less

  • AWS Activate credits. Startups can apply for $1,000 or more in credits, often through an accelerator or incubator. This could cover most of Year 1's AWS bill.
  • Compute Savings Plans once usage is steady (after about 3 months of production): 20–50% off Fargate for a 1-year commitment. RDS Reserved Instances save about 30–40% on the database.
  • ARM (Graviton) Fargate is about 20% cheaper than x86 at the same size. It needs the images built for linux/arm64, which they support.
  • ClamAV: move the virus scanner to its own small worker, or scan with Amazon GuardDuty Malware Protection for S3. The API tasks can then drop from 4 GB to 1 GB each.
  • Logs: keep production logs 30 days in CloudWatch and archive to S3 for longer. Turn off Container Insights in beta.
  • One NAT gateway in beta, and VPC endpoints (already done for S3) before adding more.
  • Scale beta to zero out of hours (the lean setup above).

8Checklist: from development to production

  1. Decide the region (B11): Cape Town or Ireland. Enable Cape Town on the account if chosen.
  2. Set up the accounts: - an AWS Organization with separate development, staging and production accounts; - MFA everywhere; - IAM Identity Center for sign-in; - a budget alert on every account.
  3. Apply the staging Terraform, set the secrets, run alembic upgrade head, and smoke-test with real test providers.
  4. Restore drill 1: restore the database to a point in time and time it (target: back within 4 hours, at most 1 hour of data lost).
  5. Real providers: - the ID-check partner (B5); - the payment and escrow partner (B7, after counsel's opinion); - Hubtel sender ID; - an approved WhatsApp template.
  6. Security review, WAF rules on, alarms tested (the email arrives), and the runbooks (docs/runbooks.md) walked through.
  7. Production: apply the Terraform with production sizes, load-test the pilot's expected traffic, then do the soft launch (11 Dec 2026).
  8. After 3 months: review actual costs against this sheet, then buy Savings Plans.
