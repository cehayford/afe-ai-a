System structure

One API holds every trust and money rule; the website, the app, WhatsApp and the payment partner all go through it.

WhatsApp

WhatsApp carries three kinds of traffic: sign-in codes, notices Afe starts, and conversations renters start. All three already run through one provider interface. Before launch, the single catch-all template in the code has to become one template per event: Meta files a template whose content is only "{{1}}" as marketing (template categorization).

Since 1 Jul 2025 Meta charges per delivered template message. Free-form replies inside an open customer service window are free, and so are utility templates sent inside one (pricing).

How a message goes out

  1. An event calls notify(). It writes one row per channel to the notifications table: in-app, SMS, WhatsApp (only if the person opted in) and email. The table is both the inbox and the outbox.
  2. The provider sends it at once. A provider reference marks the row sent; an error marks it failed with the reason.
  3. The retry-messages job runs every 5 minutes. It tries a failed row up to 3 times, after 5 and then 30 minutes, and gives up after a day. Sign-in codes are stored masked and never retried.

How a message comes in

  1. Meta checks the webhook once: GET /api/v1/webhooks/whatsapp answers its challenge when the verify token matches.
  2. Each message arrives as POST /api/v1/webhooks/whatsapp. The API checks the X-Hub-Signature-256 HMAC against the app secret and refuses anything unsigned outside development. It always answers 200, so Meta doesn't resend.
  3. A sender gets at most 30 lookups an hour, because every reply costs money.
  4. The first word picks the action: FIND searches verified homes, ALERT saves a search, STOP ends alerts and WhatsApp updates, REPORT files a scam report, VIEW links to booking. Anything else goes to "Check before you pay".
  5. The answer goes back to the same number.

Payments

Afe never holds money. Fees Afe earns go through Paystack's hosted checkout; rent a tenant pays is held by a licensed partner, and Afe only sends it instructions and records what it confirms. The rent side is built against a test partner and stays switched off until counsel's opinion (B7) names the partner and the legal structure.

What Afe asks the partner to do

A real partner is one class with the six calls of EscrowPartner (tenancies/partners.py); nothing else in the app changes.

Endpoints: POST /api/v1/tenancies/webhook for held rent and POST /api/v1/payments/webhook for fees. Both check the partner's signature before reading anything.

Safeguards already in the code

  • Every state change writes a ledger entry and an outbox row in the same database transaction.
  • Webhooks are signature-checked and idempotent on the partner's reference.
  • An amount that doesn't match, or a payment after the offer expired, raises a high-severity flag for a person.
  • Payouts go only to an account whose registered name matches the verified landlord or authorised agent.
  • Accepting an offer is refused when the pilot's total held would go over its limit.
  • A daily report to the founder lists money held, paid in, released, refunded and reconciliation differences.

Fees Afe earns

  1. The landlord taps pay: POST /api/v1/payments/verification-fee (featured listings and plans work the same way).
  2. The API opens a Paystack checkout for mobile money or card and sends the landlord there.
  3. Paystack calls POST /api/v1/payments/webhook; the API checks the HMAC-SHA512 signature and marks the fee paid. The browser's return is never trusted.
  4. The receipt PDF is ready at once. During the launch offer the fee is waived and no checkout opens.

Questions for the partner, in writing

  • Can you hold a payment and release it later on our instruction (held or delayed settlement)?
  • Can you refund a held payment to the same mobile-money wallet?
  • Can you look up the registered name on an MTN, Telecel or AT wallet and on a bank account?
  • What is the fee on the amount held, and can it be capped or tiered?
  • Do you offer a statement or transaction API we can reconcile against nightly?
  • How long does a payout to mobile money take, and how are failures reported?

Fraud detection

AI sits on top of verification, never in place of it. Five models already score in shadow next to reviewers' decisions; none can act until it beats the Phase 1 rules on real labelled cases and a second reviewer approves. Even then a model only raises a flag for a person.

ModelWhat it scoresHowWhere its labels come from
Scam wordingListing text and in-app messagesWord features plus a Naive Bayes model retrained from labels; a Claude Haiku classifier is built but offReviewer decisions, scam reports from the website and WhatsApp
PriceRent against the area and bedroom countMedian of Afe's verified listings, or the manual price survey until an area has enoughListings approved or rejected
PhotosA home's visit photos against every other home'sTwo perceptual hashes together (128 bits), so crops and colour changes still matchDuplicate-photo decisions
DocumentsOwnership and authority documentsEdit traces: PDF producer and dates, editing-software tagsReviewer decisions on documents
Linked accountsPeople sharing a Ghana Card, payout account, photos or a phone number with known fraudAccount graph rebuilt nightlyUpheld reports and rejected verifications
  • Every WhatsApp REPORT and every "Check before you pay" lookup of an unknown number is a fraud example; verified listings should produce almost none.
  • Scam wording in an in-app message puts a warning in front of both people: never pay before you view, and keep payment on Afe.
  • The money path uses rules, not models: an amount mismatch, a payment after expiry and a failed payout each raise a high-severity flag at once.
  • Before the Claude classifier is switched on, counsel confirms that sending redacted message text abroad is allowed (Act 843, B11).

Implementation plan

Four phases in 52 weeks, each ending in a gate; if a gate's criteria aren't met, the next phase waits and we fix the gap rather than move the date. Two engineers carry the software work; most of the calendar is spent on approvals, partners and verifying homes by hand.
